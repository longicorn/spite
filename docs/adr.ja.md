## ADR-0006: 予測結果における目標完了確率および遅延リスクの評価

### ステータス
承認済み。

### コンテキスト
パーセンタイル予測（P50、P80、P90など）は不確実性の全体像を提示しますが、プロジェクト管理者やステークホルダーが最も頻繁に直面する問いは「特定のマイルストーンや期日Xまでに完了できる確率は何%か」「期日Xを超過する遅延リスクは何%か」という直接的な疑問です。

明示的な目標評価機能がない場合、利用者は提示されたパーセンタイル値から手動で内分・外挿推測するか、分布曲線を目視確認するしかありませんでした。また、ADR-0004（抽象的な期間と任意の日数換算）の方針を維持し、カレンダー日付による不正確な精度偽装を避けつつ、期間と日数の換算を一貫して扱う必要があります。

### 決定事項
1. **共通の目標指定CLIオプション**:
   - `predict` および `simulate` の双方に `--target-periods <float>`（抽象期間単位の目標値）を導入する。
   - `--days-per-period` 指定時に利用可能な利便オプションとして `--target-days <float>` を導入する（`target_periods = target_days / days_per_period` により期間に換算）。`--target-days` は `--days-per-period` を必須とし、`--target-periods` との同時指定は不可とする。
   - ADR-0004 に厳格に準拠し、カレンダー日付や休日の計算は行わない。
2. **完了確率と遅延リスクの対でのレポーティング**:
   - 各シナリオ（Best、Nominal、Worst）について、以下の両方を算出してパーセンテージで報告する：
     - **完了確率（成功率）**: $P(\text{Duration} \le \text{target})$
     - **遅延リスク（超過確率）**: $P(\text{Duration} > \text{target}) = 1 - P(\text{Duration} \le \text{target})$
3. **エンジンごとの算出方式**:
   - `predict`: フィッティングされた対数正規分布の累積分布関数（CDF）および生存関数（SF）を用いて解析的に計算する。
   - `simulate`: モンテカルロ試行における完了期間サンプルから経験的割合（$\text{count}(\text{duration} \le \text{target}) / N$）として計算する。
4. **全出力形式への統合**:
   - Terminal、Markdown、HTMLレポートでは、四捨五入した整数の完了確率とその補数を1列に表示する（例：`73% (delay 27%)`）。完了確率が0%を超え0.5%未満なら`<1% (delay >99%)`、99.5%以上で遅延リスクが0%を超えるなら`>99% (delay <1%)`とする。厳密な0%または100%はそのまま表示する。シミュレーション結果は試行に基づく推定値である。
   - 機械可読な `snapshot.json` には、丸める前の完了確率と遅延リスクを保存する。
5. **完了分布上での目標値の可視化**:
   - Matplotlibを利用した可視化（HTMLレポート埋め込み画像、`--format png`、対話型`--show`）において、シナリオ分布曲線上に目標期間を示す専用の垂直参照線を描画する。実績値（Actual）の垂直線が存在する場合は線種・色・ラベルで明確に区別する。
   - ターミナルASCII分布図では、該当行に専用のインジケータで目標期間を表示する。
   - Markdownレポート内のMermaid `xychart-beta` では構文制約により垂直線の描画は見送り、要約表による報告に留め、Mermaidの垂直線対応は将来の課題とする。

### 影響とトレードオフ
- **メリット**:
  - ステークホルダーの納期に関する疑問に対し、具体的な確率値で即座に回答できる。
  - カレンダー処理の複雑性を持ち込まず、ADR-0004 の設計原則と綺麗に調和する。
  - パラメトリック予測（`predict`）と構造シミュレーション（`simulate`）で一貫した利用体験を提供する。
- **デメリット・制約**:
  - 算出される確率はモデルの前提条件（規模、不確実性、最頻値など）に基づく条件付き確率であるため、高い確率であってもブラックスワン的な事態を排除するものではない旨の注意を促す必要がある。

## ADR-0005: 予測結果共有のための自己完結型HTMLレポート形式の採用

### ステータス
承認済み。

### コンテキスト
Spiteの主な成果物は確率分布による納期予測と振り返り評価です。Markdownは開発者がリポジトリやエディタ内で確認するには適していますが、ビジネスステークホルダーやプロダクトマネージャー、外部パートナーに結果を共有する際には、特別なMarkdownビューアを介さずにリッチで視認性の高いレポートを提示することが求められます。

また、PDF形式のエクスポートをネイティブにサポートしようとすると、ヘッドレスブラウザや重い外部バイナリ（WeasyPrint、Chromium等）の依存関係が発生し、ツールのポータビリティやクロスプラットフォーム動作を損なうリスクがあります。さらに、HTMLと画像ファイル（PNG）が分かれている場合、Slackやメール等で単体配布した際にリンク切れが発生しやすくなります。

### 決定事項
1. **各レポートコマンドへの `--format html` の導入**:
   - レポートを生成するコマンド（`predict`、`simulate`、`history`）において `--format html` を指定可能にする。
   - デフォルトのドキュメント形式としてはMarkdownを維持する。
2. **単一ファイル完結（スタンドアロン）出力**:
   - CSSはHTML内の `<style>` タグにインラインで埋め込む。
   - 予測分布グラフや実行チャート（PNG画像）が存在する場合、HTML出力時はBase64エンコードデータURI（`data:image/png;base64,...`）として直接インライン埋め込みを行う。
   - 外部CDNやネットワーク接続に依存せず、ローカルファイル（`file://`）としてダブルクリックするだけでオフラインでも完全に閲覧可能とする。
3. **ブラウザ印刷によるPDF化への対応**:
   - 印刷用CSSメディアクエリ（`@media print`）を整え、利用者がブラウザの標準印刷機能（PDFに保存）を通じて高品質なPDFを出力できるようにする。これによりツール本体への重いPDF生成ライブラリの追加を回避する。
4. **軽量なレンダリング設計**:
   - レンダリング機構は軽量に保ち、過剰な外部ライブラリ依存を避ける。

### 影響とトレードオフ
- **メリット**:
  - HTMLファイル1つを添付・送付するだけで、誰のブラウザでも同一の綺麗なレイアウトでレポートを閲覧できる。
  - 重いネイティブPDFライブラリに依存せず、ブラウザの印刷機能と連携して綺麗なPDFが得られる。
  - 共有時の画像ファイルリンク切れリスクが完全に解消される。
- **デメリット・制約**:
  - Base64インライン埋め込みにより、画像を含むHTMLファイルのサイズがテキストのみのMarkdownより大きくなる。

## ADR-0004: 抽象的な期間と任意の日数換算

### ステータス
承認済み。ADR-0003に代わります。

### 決定
両機能は抽象的なperiodで期間を表します。利用者は任意で1 periodあたりの日数を指定できます。日数は単純な概算であり、カレンダー日付や休日は計算しません。作業量のPointと処理速度のモデル化は未実装です。

### 影響
日付に見える精度を与えずに期間を比較できます。一方、実際の完了日を求めるには別途カレンダーとチームの事情を考慮する必要があります。

## ADR-0003: 祝日を考慮せず土日のみを除外する稼働日計算方式の採用

### ステータス
廃止。ADR-0004に置き換え済み。

### コンテキスト
プロジェクトの納期予測では、人間が扱うカレンダー日付（YYYY-MM-DD）と、統計モデルが計算に用いる連続または離散の稼働日数との双方向変換が必要です。

しかし、祝日カレンダーの取り扱いは国や地域、企業の個別休業日など多様な外部依存があり、ツールの初期実験段階でこれらを組み込むと依存ライブラリの増加や保守コストの上昇を招き、確率分布モデルの妥当性検証という本来の目的に集中できなくなる懸念がありました。

### 決定事項
1. **土日のみを非稼働日として除外する**:
   - 土曜日および日曜日を一律に非稼働日と定義する。
   - 月曜日から金曜日までを稼働日（重み1.0）として扱う。
2. **稼働日数とカレンダー日付の決定論的相互変換**:
   - `business_days_between(start_date, end_date)` により、開始日を0日目として終了日までの稼働日数を数える。
   - 終了日が土日の場合、その土日自体は稼働日数にカウントしない。
   - 小数の稼働日数を日付に変換する際は、各機能が整数日数に丸めて `add_business_days` に渡す。Predictは最も近い整数に、Simulationは切り上げる。
3. **祝日カレンダーの保留**:
   - 国民の祝日や特別休暇への対応は、将来の拡張プラグインまたは設定オプションとして保留する。

### 影響とトレードオフ
- **メリット**: 外部カレンダーライブラリへの依存がゼロになり、高速かつ決定論的で環境依存のない軽量な計算が可能になる。確率予測モデルの実験とアルゴリズムの探求に専念できる。
- **デメリット・制約**: 大型連休（ゴールデンウィークや年末年始など）を含む期間の予測において、実稼働日数が過大評価され、予測される達成目標日が実際よりも前倒しに算出される傾向が生じる。
