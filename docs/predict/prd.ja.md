# 製品要求仕様書 (PRD): Predict

[English Document](prd.md)

本書は`spite predict`の仕様です。製品全体の範囲は[SpiteのPRD](../prd.ja.md)、設計判断は[PredictのADR](adr.ja.md)を参照してください。

## 1. ビジョンと背景

ソフトウェア開発において、納期は単一の確定した日付として求められがちです。しかしソフトウェア工学は本質的に高い不確実性や複雑性、変動性を内包しており、納期を単一の点として扱うことは不正確な計画や潜在的なプロジェクトリスクの原因となります。

**Spite** は、ソフトウェア開発の納期を単一の固定日ではなく**確率分布**として捉えてモデル化するための実験用ツールです。「システムの納期とは確率分布である」（Walker Royce氏の提唱やBent Flyvbjerg教授らの実証研究）という思想を着想の起点とし、以下の実現を目指します。
- プロジェクト初期段階から仮定の確率分布を設定する
- 前提条件（シナリオ、パラメータ、分散）を継続的かつ動的に調整・更新する
- 完了した開発実績を過去の確率モデルと比較・評価し、予測精度の妥当性を検証する

Spiteでは、ストーリーポイントやベロシティといった主観的な見積もり単位ではなく、完了までの実期間（リードタイム）に着目します。

## 2. 対象ユーザーと利用シーン

### 対象ユーザー
- 経験的・確率論的なプロジェクト予測手法を求めるエンジニアリングマネージャー、テックリード、プロジェクトマネージャー
- 恣意的な単一期日コミットに頼らず、ステークホルダーへ達成確率や信頼区間を提示したいアジャイル／スクラムチーム

### 主な利用シーン
1. **将来予測（予測モード）**
   - 開発着手前または開発期間中において、開発開始日と目標想定納期をもとに完了確率分布および達成目安日（P50、P80、P90）を算出する。
2. **実績振り返り（振り返りモード）**
   - 案件完了後、実際にかかった期間が当初の確率的見通しに対してどの位置にあったか（パーセンタイル、乖離日数、極端な遅延テールの発生有無など）を評価する。

## 3. 製品スコープと機能要件

### 3.1. CLIコマンド: `spite predict`

`spite predict` は想定納期を基準に分布を計算します。

#### 入力パラメータ
- `--start-date` (YYYY-MM-DD, 必須): 開発開始日。
- `--deadline` (YYYY-MM-DD, 必須): 当初の想定納期。開始日より後で、間の稼働日数が正になる日付を指定します。
- `--actual-end-date` (YYYY-MM-DD, 任意): 実際の開発終了日。開始日以降の日付を指定できます。
- `--best-factor` (浮動小数点数, 既定値: `0.8`): 最善シナリオのピーク期間を算出するための係数（$0 < \text{best-factor} < 1$）。
- `--worst-factor` (浮動小数点数, 既定値: `1.5`): 最悪シナリオのピーク期間を算出するための係数（$\text{worst-factor} > 1$）。
- `--sigma` (浮動小数点数, 既定値: `0.5`): 3シナリオ共通の対数スケール形状パラメータ $\sigma$（$\sigma > 0$）。
- `--format`（`terminal`、`markdown`、既定: `terminal`）: 出力形式。Markdownには入力条件、分位点、Mermaidの分布図、および指定時の実績評価を含めます。
- `--output`（パス、任意）: terminalモードではグラフ画像、Markdownモードではレポートの保存先。
- `--show` (フラグ, 任意): GUIバックエンドを用いてグラフ画面を表示。
- `--distribution` / `-d` (文字列, 既定値: `lognormal`): 分布種別（現時点では `lognormal` をサポート）。

### 3.2. 予測モード（`--actual-end-date` 未指定時）
- `--start-date` から `--deadline` までの稼働日数を計算します。
- 以下の3シナリオを生成します。
  - **最善シナリオ (Best)**: ピーク稼働日数 = 通常ピーク $\times \text{best-factor}$
  - **通常シナリオ (Nominal)**: ピーク稼働日数 = 想定納期の稼働日数
  - **最悪シナリオ (Worst)**: ピーク稼働日数 = 通常ピーク $\times \text{worst-factor}$
- 各シナリオについてパーセンタイルを算出します。
  - **P50** (中央値): その日までに完了する確率が50%となる期日
  - **P80**: 完了確率80%の期日
  - **P90**: 完了確率90%の期日
- terminalモードでは、既定でASCIIグラフと日付表を出力し、`--output` または `--show` の指定時はmatplotlibでグラフを描画します。Markdownモードでは `--output` でレポートを保存し、省略時は標準出力に表示します。`--show` は併用できません。

### 3.3. 振り返りモード（`--actual-end-date` 指定時）
- 予測モードの3分布を表示し、必要に応じて実績期間まで横軸を拡張します。
- 実績期間を**通常シナリオ**に照らして評価します。
  - 想定納期との稼働日数差および割合（例: 「実績は想定納期よりN稼働日 (X.X%)遅れて/早く完了しました」）。
  - 通常シナリオの累積分布関数 (CDF) からの実績パーセンタイル。
  - 通常シナリオのP90との乖離日数。
  - 実績がP99.9を超える場合、生存関数 (SF) による実績以降完了確率の表示（極端なテールリスクの検出）。
- 画像には実績マーカー、ターミナルとMarkdownには評価サマリーを表示します。

## 4. 技術および数学的アーキテクチャ

### 4.1. 稼働日計算
- 土曜日および日曜日を非稼働日として扱います。
- 祝日は現時点では除外せず、将来のカレンダー拡張対象とします。
- カレンダー日付と稼働日数との変換は単調増加性を保って計算します。

### 4.2. 確率分布モデル
- **対数正規分布 (Lognormal Distribution)**:
  $$\text{mode} = \exp(\mu - \sigma^2) \implies \mu = \ln(\text{mode}) + \sigma^2$$
  各シナリオのピーク稼働日数をmodeとしてパラメータを決定します。
- パーセンタイルおよび累積確率は `scipy.stats.lognorm` を用いて算出します。

## 5. スコープ外事項および将来マイルストーン

以下の項目は現行バージョンの対象外とし、将来の拡張課題とします。
- **過去データセットからの自動校正**: GitHub、GitLab、Jira等のIssue/PR履歴データからの $\sigma$ や係数の自動推定。
- **発展的確率分布**: 泥沼化・極端な遅延に対応するスプライス分布（対数正規分布＋一般化パレート分布／パレート分布）や、テスト収束予測向けのWeibull分布。
- **祝日および柔軟なカレンダー対応**: 各国の祝日カレンダーやチーム独自の休暇設定。
- **永続化ストレージ**: 定常的なスプリントトラッキングに向けたデータベースやファイル保存。
