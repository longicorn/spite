# 製品要求仕様書：ローカルGit履歴

[English](prd.md)

`spite history`は現在のブランチのHEADから到達できる履歴のうち、指定した祖先コミットまたはタグ以降を報告します。リリース済みの状態を表すブランチを対象としますが、Spiteは実際にリリースされたかを検証しません。ブランチのチェックアウトと祖先を指す`--base`が必要です。`--base`には`master`などのブランチ名、タグ、コミットIDを指定できます。対象は`base..HEAD`、つまりHEADからたどれ、baseからはたどれないコミットで、範囲内のマージ済みブランチのコミットも含みます。起点とその履歴は対象外です。ブランチの先端は移動するため、固定した起点にはリリースタグやコミットIDを使います。baseとHEADが同じ場合、対象範囲は空です。

複数の機能ブランチをマージしたリリース先を分析する場合は、そのリリース先をチェックアウトし、マージ前の祖先を`--base`に指定します。例えば前回リリースのタグを起点にできます。`--base`はマージ済みの機能ブランチを個別に選ぶ指定ではありません。機能ブランチの先端を指定すると、その先端と祖先は対象範囲から除外されます。`--base main`が現在のHEADと同じ場合は対象が空になります。

マージ以外のコミットをそれぞれ1つの観測された作業単位とし、マージコミットは合流として別に数えます。親子関係の図、観測された分岐の数、直列の履歴か並列経路があるかを表示します。これはGit履歴の構造であり、実際のタスク依存関係、ブランチ名、同時作業を証明するものではありません。squash merge、rebase、cherry-pickや、取得できない履歴・shallow cloneによって、元の開発構造が見えない場合があります。

観測期間は、対象コミットのcommitter時刻の最小値から最大値までを暦日で測ります。最初のコミット前に作業が始まっていた可能性や、時刻の変更、週末・祝日・中断期間を含むため、実際の開発期間ではありません。対象コミットがなければ期間はありません。`--days-per-period`を指定すると、この期間を単純な倍率で概算periodに換算します。

`--output`を指定すると、指定したルートの`history/<実行ID>/`にレポートとバージョン付きスナップショットを保存します。省略するとMarkdownを標準出力に表示します。任意の`--forecast-id`で同じルートにある予測を読み込み、`--forecast-kind simulate`（既定）または`predict`で種別を選べます。比較には`--days-per-period`と1件以上のコミットが必要です。通常シナリオのP50・P80・P90と観測期間を並べますが、観測期間は実績作業期間の代用値です。途中で更新したシミュレーションは経過期間を含む合計予測を使います。
